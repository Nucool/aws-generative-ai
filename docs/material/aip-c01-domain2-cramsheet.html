2.1 Agentic AI solutions and tool integrations

2.1.1 Autonomous systems with memory & state management

Strands AgentsAWS Agent SquadMCPBedrock AgentCore
Key: Multi-agent systems → Strands Agents / Agent Squad. Agent-tool interaction protocol → MCP. Persistent state / graph-based orchestration / checkpointed replay → LangGraph-style frameworks.
Trap: "graph execution + durable state + rollback/replay" → a purpose-built agent framework (LangGraph). Step Functions Map "to simulate agent memory" = red flag (bending a service to a job it wasn't built for). SageMaker Pipelines = ML train/deploy, not agent runtime.

2.1.2 Structured reasoning (ReAct, chain-of-thought)

Step Functions (ReAct)chain-of-thought
Key: Break a problem into logical steps via Step Functions ReAct — one state per step (observation / reasoning / action) with a specific prompt each, plus built-in retry/error handling.
Trap: "single state that stuffs the entire conversation history into every prompt" = not structured and grows inconsistent as history balloons. Structured = separate controlled states, not one giant prompt.

2.1.3 Safeguarded workflows (controlled FM behavior)

Step Functions stopping conditionsLambda timeoutsIAM boundariescircuit breakers
Key: Bound agent behavior with stopping conditions, timeouts, IAM resource boundaries and circuit breakers to prevent runaway loops.

2.1.4 Model coordination / ensembles

specialized FMscustom aggregationmodel selection frameworks
Key: Multiple different tasks that must be combined → supervisor agent orchestrating specialized sub-agents (quantitative / news / summarization) with aggregation.
Trap: "decentralized network, each agent independent, talks directly to users" = no coordination → wrong when results must be combined. Supervisor (centralized) beats decentralized for combined output.

2.1.5 Human-in-the-loop / collaborative AI

Step Functions (review/approval)API Gateway (feedback)Amazon A2I
Key: Orchestrate review/approval with Step Functions; collect feedback via API Gateway. A2I = human review of AI-generated output/predictions (integrates back into SageMaker for retraining).
Watch: A2I = review generated output. Ground Truth / GT Plus = label raw data to build training sets. Answer follows what the option text states, not the service's theoretical reach.

2.1.6 Intelligent tool integrations

Strands APIstandardized function definitionsLambda (error handling, param validation)
Key: Reliable tool ops = standardized function definitions + Lambda for parameter validation and error handling. Bedrock Agent action group Lambda handles the external call/auth.
Trap: Agent calling an external API → Action Group + Lambda inside the agent flow (Lambda does OAuth/token). Passing a token into the agent from outside = wrong direction. Caching a 30-min token in CloudFront = stale-token risk.

2.1.7 Model extension frameworks (MCP servers)

Lambda (stateless MCP server)ECS (complex MCP tools)MCP client libraries
Key: Lightweight tool access → Lambda stateless MCP server. Heavy/complex tools → ECS MCP server. MCP client libs = consistent access.

2.2 Model deployment strategies

2.2.1 Deploy FMs by application needs

Lambda (on-demand invoke)Bedrock Provisioned ThroughputSageMaker endpoints (hybrid)
Key: Match the deployment: on-demand for spiky, provisioned for guaranteed throughput, SageMaker endpoints for hybrid/self-hosted.
Watch (SageMaker inference types): Real-time = payload ≤6 MB, <60 s. Async = large payload (≤1 GB), long jobs (≤1 h), request/response + scale-to-zero. Batch Transform = whole dataset offline, not request/response. Serverless = intermittent traffic.
Trap: payload >6 MB or runtime >60 s → rules out real-time. "request/response" rules out batch. Async is the classic "large payload + long + cost-effective + request/response" answer.

2.2.2 LLM-specific deployment challenges

container-based deploymentGPU utilizationmodel loading strategies
Key: LLMs need memory-optimized containers, GPU planning, token-processing capacity, and preloaded model weights.
Trap: "lazy loading" / scale-to-zero / min instances = 0 → cold start (red flag for low-latency real-time). Fix cold start with nonzero minimum instances + preload model at container start.

2.2.3 Optimized deployment (balance performance & resources)

smaller pre-trained modelsAPI-based model cascadingmodel distillation
Key: Routine queries → smaller/cheaper model or cascade. Distillation: teacher (large) → student (smaller, cheaper). Distill from Pro → Lite, never to a larger model.
Trap: Distillation student bigger than teacher (Pro → Premier) = wrong, raises cost. When synthesizing training data, use prompts only (teacher regenerates responses), not the stored prompt-response pairs.

2.3 Enterprise integration architectures

2.3.1 Enterprise connectivity with FMs

API integrationsevent-driven (loose coupling)data synchronization
Key: Legacy integration via APIs; loose coupling via event-driven architecture; keep data in sync with established patterns.

2.3.2 Enhance existing apps with GenAI

API Gateway (microservices)Lambda (webhook handlers)EventBridge (event-driven)
Key: S3 upload triggers pipeline → EventBridge rule → Step Functions directly (least overhead). EventBridge for event-driven integration.
Trap: "S3 notification → Lambda → invoke Step Functions" adds a needless Lambda hop; EventBridge → Step Functions as a direct target is cheaper. Presigned URL for mobile/client uploads, not PutObject.

2.3.3 Secure access frameworks

identity federationRBACleast-privilege API accessIAM Identity Center
Key: Federate identity between FM services and enterprise; enforce RBAC + least-privilege on model/data access. Q Business RBAC → IAM Identity Center + security-group mapping.
Trap: Building a custom API Gateway + Lambda access layer, or CloudWatch alarms to "revoke sessions", when native RBAC exists = overhead + detective-not-preventive.

2.3.4 Cross-environment / data-compliance across jurisdictions

AWS Outposts (on-prem)AWS Wavelength (edge)secure routing
Key: On-prem data integration → Outposts. Edge/low-latency deployment → Wavelength. Keep secure routing between cloud and on-prem.

2.3.5 CI/CD pipelines & GenAI gateway architectures

CodePipelineCodeBuildcentralized abstraction layersecurity scans + rollback
Key: Automated testing + security scans + rollback in CI/CD; a centralized abstraction layer (GenAI gateway) for observability and control of consumption.

2.4 FM API integrations

2.4.1 Flexible model interaction systems

Bedrock APIs (sync)SQS (async)API Gateway (request validation)
Key: Sync requests via Bedrock APIs; async processing via SDK + SQS; API Gateway for custom clients with request validation.
Trap: SQS/queue = async — a red flag when the requirement is real-time / sub-second chat.

2.4.2 Real-time interaction (immediate feedback)

Bedrock streaming APIsWebSockets / SSEAPI Gateway chunked transfer
Key: "user waits too long for the first word / first token" → response streaming (deliver tokens incrementally). WebSockets or SSE for real-time text.

2.4.3 Resilient FM systems

SDK exponential backoffAPI Gateway rate limitingfallback / graceful degradationX-Ray
Key: Reliability = exponential backoff on throttling, API Gateway rate limiting, fallback for degradation, X-Ray for cross-service observability.

2.4.4 Intelligent model routing

Step Functions (content-based routing)Bedrock Intelligent Prompt RouterAPI Gateway request transform
Key: Route to specialized FMs by content/complexity. Same-family routing → Intelligent Prompt Router (+ fallback). Static config or Step Functions for dynamic routing.
Trap: Intelligent Prompt Router routes within one family only. Cross-family (Titan / Llama ↔ Claude) → custom routing. "Small model self-assesses then escalates" doubles latency/cost for complex queries.
