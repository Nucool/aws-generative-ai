3.1 Input and output safety controls

3.1.1 Content safety for harmful inputs

Bedrock Guardrails (content filters)Step Functions + Lambda (moderation)
Key: Filter harmful user input with Guardrails content filters; custom moderation via Step Functions + Lambda; real-time validation before inference.

3.1.2 Content safety for harmful outputs

Guardrails (filter responses)FM evaluations (toxicity)text-to-SQL (deterministic)
Key: Filter harmful outputs with Guardrails; specialized FM evals for toxicity; text-to-SQL to force deterministic results instead of free-form generation.

3.1.3 Accuracy verification / reduce hallucinations

Bedrock KB (grounding)Contextual grounding checkconfidence + semantic similarityJSON Schema
Key: Reduce hallucination by grounding on a Knowledge Base + contextual grounding check; verify with confidence scoring + semantic similarity; enforce structure with JSON Schema.
Trap: "incorrect / inaccurate info" → Contextual grounding check (a Guardrails feature) + KB grounding, not more orchestration. Reducing hallucination is a content/grounding fix, not a throughput fix.

3.1.4 Defense-in-depth safety

Comprehend (pre-filter)Bedrock (model guardrails)Lambda (post-validation)API Gateway (response filter)
Key: Layer protections: Comprehend pre-processing filter → Guardrails at the model → Lambda post-processing validation → API Gateway response filtering.

3.1.5 Advanced threat detection (adversarial inputs)

prompt-injection / jailbreak detectioninput sanitizationsafety classifiersadversarial testing
Key: Detect prompt injection and jailbreaks; sanitize inputs; use safety classifiers and automated adversarial-testing workflows.

3.2 Data security and privacy controls

3.2.1 Protected AI environments

VPC endpointsIAM policiesLake FormationCloudWatch (monitor access)PrivateLink
Key: Network isolation with VPC endpoints / PrivateLink (no public internet); IAM for secure access patterns; Lake Formation for granular data access. Distributed training: inter-container traffic encryption + VPC endpoint + PrivateLink + least-privilege (read-only) role.
Trap: Don't pick two overlapping choices (S3 VPC endpoint + PrivateLink-to-S3 = same job). "read-only execution role" is a valid least-privilege answer (write to output path is separate). Network Firewall inspect ≠ encrypt; NSG "accept inbound" ≠ secure.

3.2.2 Privacy-preserving systems (PII protection)

Comprehend + Macie (detect PII)Bedrock native privacyGuardrails (filter output)S3 Lifecycle (retention)
Key: Detect PII with Comprehend/Macie; filter output with Guardrails sensitive information filters; enforce retention with S3 Lifecycle.
Trap: "data cannot be retained longer than necessary" → S3 Lifecycle expiration/delete, NOT "move to archival" (archival keeps it longer). Role-based PII exposure → Cognito group + ApplyGuardrail (runtime mask), one KB — not two KBs.

3.2.3 Privacy-focused systems (maintain utility)

data maskingComprehend PII detectionanonymizationGuardrails
Key: Mask/anonymize sensitive data while keeping FM utility. Guardrails PII filters + masking preserve function.
Watch: Macie = scan PII in S3 (storage). Comprehend = detect/redact PII in text (pipeline). Guardrails = filter PII at the model boundary (runtime, role-aware). Rekognition = images, never text PII.

3.3 AI governance and compliance mechanisms

3.3.1 Compliance frameworks

SageMaker model cardsGlue (data lineage)metadata taggingCloudWatch Logs (decision logs)
Key: Programmatic model cards, automatic data-lineage tracking, metadata tagging for source attribution, comprehensive decision logs.

3.3.2 Data source tracking / traceability

Glue Data Catalogmetadata taggingCloudTrail (audit)Bedrock Model Invocation Logging
Key: "log FM usage + track prompt lineage + model I/O metadata" → Bedrock Model Invocation Logging (captures prompt input + output + metadata to S3/CloudWatch). CloudTrail = API-level audit.
Trap: CloudTrail alone does not capture prompt/response content — for I/O metadata you need Model Invocation Logging.

3.3.3 Organizational governance systems

SCP (org-wide)CloudFormation StackSetsIAM Identity Center permission sets
Key: Restrict which models can be invoked org-wide → SCP (matches model ID) + IAM Identity Center permission sets. Deploy a guardrail to every account → StackSets. Enforce guardrail usage → SCP requiring a guardrail identifier.
Trap: RCP does not support Bedrock — can't control Bedrock model access with an RCP (SCP does). StackSets that provision IAM roles per account = more overhead than one SCP. Bedrock FMs don't take resource-based policies per model.

3.3.4 Continuous monitoring & advanced governance

automated misuse/drift detectionbias drift monitoringtoken-level redactionresponse loggingoutput policy filters
Key: Automated detection of misuse/drift/policy violations, bias-drift monitoring, alerting + remediation, token-level redaction and output policy filters for audit readiness.

3.4 Responsible AI principles

3.4.1 Transparent AI (explainability)

reasoning displaysCloudWatch (confidence metrics)evidence / source attributionBedrock agent tracing
Key: User-facing reasoning displays, confidence/uncertainty metrics, evidence for source attribution, agent tracing for reasoning traces.

3.4.2 Fairness evaluations (unbiased outputs)

CloudWatch fairness metricsPrompt Management / Prompt Flows (A/B)LLM-as-a-JudgeSageMaker Clarify
Key: Predefined fairness metrics; systematic A/B testing via Prompt Management/Flows; automated model evals with LLM-as-a-Judge. Clarify = detect bias / class imbalance in datasets.
Watch: A/B testing = compare multiple versions to select the best (distinct from Canary/Blue-Green/Linear, which are safe-rollout of one model).

3.4.3 Policy-compliant AI systems

Guardrails (policy-based)model cards (limitations)Lambda (compliance checks)
Key: Guardrails configured to policy; model cards documenting FM limitations; Lambda for automated compliance checks.

Domain 3 golden rule: preventive beats detective; put each control on the service that actually performs it (Guardrails = safety, IAM/SCP = access, Model Invocation Logging = I/O audit); and match every Guardrails requirement to its specific component.
